## 硬规则

1. **与代码状态无关。** 文档不得引用任何具体修订：不写函数名、文件名、分支名、提交号，不写"当前实现如何如何"。回滚或重写代码之后，这些文档必须仍然完整可读、仍然有效。
2. **验收必须可判定。** 每条要求都要给出能执行的判定方式——跑一个作业、看一个数、检查一份清单。不接受"看起来对"。
3. **编号稳定。** 02 和 03 引用 01 的编号（`F1.1`、`P4`、`N2` 等）。01 若增删条目，应在 02 / 03 里同步。
4. **01 里不写实现。** 01 只说"要什么"，不说"怎么做"。

## 数据事实的边界

01 里只保留**可从数据本身实测**的事实（例如各时刻采样点集的异同）。代码侧的现象、某个版本的报错、某个模块的行为，一律不写。

## 需要在 03 里记录的量级

- 四类数据通道在 Lt=72, Ne=128, Np=216, Nc=3 下的体积：`v2v` 约 0.14 GiB、`v2p` 约 0.71 GiB、`p2v` 约 0.71 GiB，合计约 1.6 GiB，另有稀疏 `p2p`。
- 成本公式：收缩次数 = 采样场景数 × Π(分裂顶点的腿偏移类数)。
- 采样场景数的量级：单个采样池内 r 个点端对应 Bell(r)（r=4 → 15，r=8 → 4140）。
- 两种采样池划分（01 的 F5 分叉）各自的权重解析式与验证方式。
