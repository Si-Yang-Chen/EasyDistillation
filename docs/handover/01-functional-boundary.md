# 01 功能边界

> 这份文档定义"要做什么、做到什么程度算做到、明确不做什么"。
> 它不描述实现。文档 02（架构设计）和 03（注意事项）都必须能逐条追溯到这里的编号。

---

## 1 目标

计算**含跨时间结构的流算符插入的多点函数**，并让它与不带流的多点函数走**同一条**流程：同一个图表示、同一个缩并入口、同一套采样记账。不存在"时间方向的流另起一条路"。

判定"同一条路"的标准：把流的插入换成任意别的介子算符（或不插入），脚本的其余部分不需要改。

---

## 2 必须支持

每一条都附**验收方式**。验收方式必须是可执行、可判定的（跑一个作业、看一个数），不是"看起来对"。

### F1 多点结构与时刻

| 编号 | 要求 | 验收 |
|---|---|---|
| F1.1 | 任意顶点数的多点函数。顶点间的连接拓扑由邻接关系给出，受夸克数守恒约束（每个顶点的夸克出入线数必须与它代表的强子一致）。 | 构造 N = 2,3,4,5 个顶点的图，全部能展开并给出有限结果。 |
| F1.2 | **每个顶点独立指定时刻**（单点）。任意组合都允许，包括不单调、跨大间隔。 | 随机取 100 组顶点时刻组合，逐组计算，与"逐个时刻单独算再拼接"一致。 |
| F1.3 | **其中一个顶点可以指定为时刻区间**（一次给一串时刻），其余顶点给单点。区间端点可以是任意起点、任意长度。 | 取一个顶点给 `[0..Lt-1]`，其余给固定时刻，结果与逐个时刻单独算的逐元素相等。 |
| F1.4 | 时刻区间的顶点是**可交换的**：换另一个顶点当区间，得到的应当是同一个二元函数，只是输出维度的摆放不同。 | 两点函数里分别让顶点 0 和顶点 1 当区间，两次结果在逐 `(t1, t2)` 对齐后相等。 |
| F1.5 | **重子端点**：源端 3 出 0 入、汇端 0 出 3 入的顶点必须支持。 | 两点重子函数能算，顶点下标维度为 3 夸克 × (自旋, 本征)。 |
| F1.6 | **重子与流插入共存**：若能低成本同时支持介子与重子顶点，则一并实现；否则在需要重子的路径上留**显式 TODO**。不允许以崩溃、静默错或内部错误代替"不支持"的表达。 | 若实现：重子—流共存图给出有限结果。若留 TODO：走到重子路径时抛出**说明原因**的错误（明确说出"重子顶点与流共存未实现"），不得是内部类型/结构错误。 |

### F2 时间差结构的流

| 编号 | 要求 | 验收 |
|---|---|---|
| F2.1 | 流算符的两条腿可以有**任意整数时间差**，管线中不得存在"时间差必须是 ±1"或"必须是一链"的假设。 | 用同一个算符定义、只改时间偏移，取 Δt = ±1, ±2, ±5, 0 都能跑完管线并给出结果（数据是否存在是数据侧的事，管线不得拒绝）。 |
| F2.2 | 时间偏移是**算符项的属性**，不是顶点的属性。同一个顶点上不同项可以有不同偏移。 | 一个含 2 项（偏移分别为 (0,+1) 和 (+1,0)）的流，两条腿各自接在正确的端点时刻上。 |
| F2.3 | 一个图里可以插入**任意多个**带时间差的流算符，各流的时间差互相独立，并且**精确枚举**全部组合，不做近似。 | 插入 2 个和 3 个分裂流，所有项组合都被枚举并求和，结果与"逐个流单独算再组合"一致。 |
| F2.4 | 多个流共用同一份数据时，每个流的项必须能被独立寻址，不得隐含"全局只有一个流"的假设。 | 两个流用不同的时间差，交换两者的数据后结果按预期改变。 |
| F2.5 | 带时间差的流可以出现在**任何**介子型顶点上，包括源端、汇端、中间顶点。 | 把流分别放在三个不同顶点上，三种都能算。 |

### F3 资源与规模

| 编号 | 要求 | 验收 |
|---|---|---|
| F3.1 | **设计时必须为每一块大数组明确生命周期**：谁创建、谁持有、何时释放。 | 文档 02 对每一块大数组给出生命周期；文档 03 给出实测峰值。 |
| F3.2 | **同一份数据不得在显存里重复驻留**。同一内容以不同名字持有两份属于设计缺陷，每块数据必须有唯一的持有者。 | 文档 02 为每块数据指定唯一持有者，并列出所有持有者清单供审查。 |
| F3.3 | 时间平移只搬运时间实参，**不得为平移准备副本**。 | 对同一份数据以不同 Δt 反复取值，常驻显存不随 Δt 个数增加。 |
| F3.4 | 任何缓存都是**有界**的：条数由结构决定，与时间点数、与流个数无关。 | 把时间点数从 1 提到 Lt、流个数从 1 提到 3，缓存条数不变。 |
| F3.5 | 总显存占用以**数据本身**为主要项，文档 03 须给出量级公式。 | 文档 03 提供公式，且实测量级与之相符。 |

### F4 数据规模

| 编号 | 要求 | 验收 |
|---|---|---|
| F4.1 | 支持生产规模：Lt=72, Ne=128, Np=216, Nc=3。 | 在该规模下跑通一次完整的多点计算。 |
| F4.2 | 支持按低模数（`usedNe`）与采样点数（`usedNp`）截断，且截断后的结果与"全量算完再截断"一致。 | 对同一组态取 usedNe ∈ {1, 8, 128}，结果与全量结果的对应子块相等。 |
| F4.3 | 支持多个组态（系综平均由调用方做，管线只负责单个组态正确）。 | 至少 3 个组态跑通且结果互不相同（排除常量假象）。 |

### F5 采样池划分（可配置）

采样的统计设计本身是一个**可选分叉**，不是写死的假设。两种已知设计：

- **A**：一个采样池跨所有时刻（所有时间片共用同一组采样点）。
- **B**：每个时刻独立重抽一个采样池。

当前生产数据采用 **B**（可实测：各时刻的坐标集不同），因此 **B 为主线**。A 作为可选分叉必须同样可用。

| 编号 | 要求 | 验收 |
|---|---|---|
| F5.1 | **采样池划分是显式输入**：哪些"顶点 × 腿"共享一个采样池，由调用方给出。权重记账**只**依赖于它。 | 同一份数据、只改划分、不改其余任何东西，结果按该划分的解析权重变化。 |
| F5.2 | 支持 A 与 B 两种划分。 | 两种划分都能跑通，且各自与解析权重一致。 |
| F5.3 | 两种划分都必须在真实数据上验证。主线取哪一种由生产数据实际使用的划分决定，并应在文档 03 记录。 | 两种划分各验一次：同一池内权重为 `C(M,k)/C(N,k)`（k 取**该池全部**点端的不同坐标数）；不同池时权重为各池权重之积。 |
| F5.4 | **顶点是否分裂不得参与权重记账**，它只决定传播子取哪个时刻。 | 固定池划分、只开关分裂标志，权重与场景数不变。 |
| F5.5 | 划分定义在"可以取点端的腿"上，只有真正处于点端状态的那些腿贡献场景。 | 同一图改为全低模端时，权重退化为 1 且场景数为 1。 |

**权重的来源（两种划分下统一说）**：权重 = 1 / （该坐标模式被包含的概率）。

- **同一池内**的 r 条腿：场景是这 r 条腿的集合划分（Bell(r)），权重 `C(M,k)/C(N,k)`，k 为不同坐标个数。
- **不同池**的腿：坐标互相独立且均匀，所以"坐标恰好相同"**不是**单独的包含事件，权重就是各池权重的**乘积**。

A 与 B 的区别只在于"哪些腿算同一个池"，权重公式本身不变。

**各编号之间的成本关系**（供文档 02 做预算，不是限制）：

一个图的收缩次数 = **采样场景数 × Π(每个分裂顶点的腿偏移类数)**。

- 第二项很小：守恒流的时间分量只有 2 类（偏移 `(0,+1)` 与 `(+1,0)`）；即便四个方向全插在同一顶点，也只有 3 类（六个空间项共享 `(0,0)`）。所以 3 个分裂流是 8 次，10 个也才 1024 次。同一顶点上偏移相同的项必须合并成一块，不进入枚举。
- 第一项才是大头：一个采样组内 r 个点端的场景数是 Bell 数（r=4 是 15，r=8 是 4140）。它**与流无关**，是既有成本。
- 因此成本以场景数为主导，多流不构成枚举爆炸。

## 3 明确不做

写清楚不做，和写清楚要做同等重要。

| 编号 | 不做的事 | 原因 |
|---|---|---|
| N1 | **局域（逐点）守恒律 / Ward 恒等式检验** | 数据里被替换掉的自由度已经按空间求和，单个格点的信息不再存在。只能做积分型检验。 |
| N2 | **多个顶点同时指定为时刻区间** | 需要"每个时刻元素各自一套偏移"的语义，与 F2.2 的项级偏移冲突。留待扩展，本版明确不支持（F1.3 只要求一个）。 |
| N3 | **非一链时间差的数据生成** | 管线必须接受任意 Δt（F2.1），但"如何为 Δt=5 造出数据"属于算符/数据侧，超出本版范围。本版只要求管线不成为障碍。 |
| N4 | **重合修正的无偏性证明（r ≥ 3）** | 本版不做新的证明，只要求权重与其所属池划分的定义一致；已知缺口在文档 03 记录。 |
| N5 | **多粒子端的完整支撑** | 图表示本身是多点通用的，但两粒子端（散射）涉及的算符构造不在本版范围。 |
| N6 | **GPU 后端之外的性能优化** | 本版只保证正确性与显存有界，不承诺最优吞吐。 |

## 4 术语与不变量

供文档 02 / 03 引用，避免歧义。

| 术语 | 含义 |
|---|---|
| **顶点** | 一个强子算符（介子或重子）的插入点。 |
| **腿** | 顶点上一条夸克线的端点。介子顶点两条（一进一出），重子源三条出、重子汇三条入。 |
| **锚时刻** | 顶点自身被赋的那个时刻。顶点的数值块在该时刻取。 |
| **腿偏移** | 该腿的时刻相对锚时刻的整数量。 |
| **分裂流** | 至少一个项的两条腿偏移不同的流算符（时间方向守恒流即此类）。 |
| **项** | 流算符的一个加项，各自带系数与两个腿偏移。 |
| **扇区** | 一个顶点的两条腿各自处于低模端还是采样点端，共四种组合。 |

**必须成立的不变量**（文档 02 的架构必须保证、文档 03 必须列出如何检验）：

- **P1 配对**：流的哪条腿接哪条夸克线，必须由**数据布局**唯一决定，不得由调用方选择。错误配对会产生一个"看起来正常"的镜像结果。
- **P2 偏移归属**：偏移属于**项**（F2.2）。把它放到顶点上会在多项流上给出错误结果。
- **P3 扇区完备**：四种扇区之和才是估计量，任何一个扇区都不是"可以忽略的小项"。
- **P4 采样记账由池划分决定**：权重 = 1 / （坐标模式被包含的概率），而包含概率由**显式给定的采样池划分**决定。同一池内按集合划分列举场景并用 `C(M,k)/C(N,k)`；不同池之间互相独立，权重相乘。**"顶点是否分裂"不是权重的输入**——它只决定传播子取哪个时刻。
- **P5 时间平移是实参搬运**（F3.1），任何"为平移预先生成数组"的实现都违反 F3。

## 5 已裁定

以下四条已定，文档 02 / 03 不再重新讨论。

1. **重子与流共存（F1.6）＝ 保留接口**。若能低成本地同时实现介子与重子，则兼容实现；否则在需要重子的路径上留下显式 TODO，错误信息必须说明原因。**不以重子共存为阻塞项。**
2. **多流枚举（F2.3）＝ 精确枚举，不做近似**。可枚举量是腿偏移**类别数**（守恒流 2 类）而非项数，主导项是与之无关的采样场景数。
3. **显存（F3）＝ 设计义务，不设硬阀值**。要求：每块大数组有明确生命周期；同一份数据不同时驻留两份；平移不准备副本；缓存条数有界。
4. **采样设计（F5）＝ 可选分叉**。两种池划分都必须可用，主线由生产数据决定。据此**采样池划分必须是显式输入**，而"顶点是否分裂"不得参与权重记账。

## 6 容易犯的推理错误

这一节只讲语义陷阱，不引用任何实现。每一条都曾被推错，而且错的方式都一样：**把"在某组数据上凑对了"当成"原理上对"**。

| 陷阱 | 为什么是错的 | 正确说法 |
|---|---|---|
| 认为"不同时刻的两条腿不可能落在同一坐标" | 两种池划分下都可能：同一个池时概率约 1/M，两个独立池时也可能恰好含同一坐标 | 该不该合并记账，取决于它们是否在**同一个池**，与"能不能重合"无关 |
| 认为"多个分裂流会造成枚举爆炸" | 可枚举量是腿偏移**类别数**（守恒流 2 类）而不是项数；10 个分裂流也才 1024 次 | 成本 = 场景数 × Π(偏移类数)，以场景数为主 |
| 把采样分组绑在"顶点是否分裂"上 | 这只在池按时间划分时成立；换成另一种划分就是错的，**且错得静默**（是偏差不是崩溃） | 分组由池划分决定（F5.1），不由分裂标志决定 |
| 用"在某组数据上算对了"当作原理正确的证据 | 两种池划分给出不同的正确权重，一组数据只能验证其中一种 | 判据必须写成"对给定池划分的解析权重成立"，而不是"与某次数值一致" |
